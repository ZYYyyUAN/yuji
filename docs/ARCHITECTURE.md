# 架构与工程要点

## 共享算法与平台边界

H5 目录是共享逻辑参考；Android 和 Windows 各自携带已适配的副本，Tap 端通过 CommonJS 模块及平台封装运行。不是四端在运行时共享同一个目录，也不依赖在线后端。

- `engine.js` / `arena.js`：对局模拟、机器人、子弹、掩体与补给。
- `ink.js`：真实对局留下的源墨斑。
- `forms.js` / `sculpture.js`：本地参数构图、高度求解与几何表示。
- `render.js` / `choose.js`：作品绘制、候选筛选与计算调度。
- H5 `sculpture-worker.js`：后台计算；Tap 端通过协作式主线程调度拆分任务。

## 持久化

浏览器使用本地存储；Tap 端以平台文件系统保存作品源数据，以存储 API 保存设置和索引相关状态。作品文件先写临时文件再 rename 提交。历史按元数据扫描，已落盘记录采用有限缓存，避免全部载入。

Android 通过包内资源和原生桥处理图片保存。Windows 使用隔离的预加载脚本 / IPC 与原生保存窗口。各端没有统一用户账号和云同步。

## 输入、生命周期与平台兼容

电脑端为键鼠，移动端为双触点摇杆；失焦或切后台暂停。Tap 平台封装集中处理 Canvas、ImageData、文件、音频、登录和相册。

原生调试发现部分 API 行为与浏览器不同：ImageData 工厂代理异常、八位十六进制透明色异常、restore/globalAlpha 与 drawImage 的透明度差异。最终实现依据真机像素探针调整绘制与背景缓存，没有把模拟器通过当作原生通过。

## 启动与作品形成

Tap 首页使用烘焙后的静态封面，进入玩法后再创建战斗和展台画布，避免首页同步运行完整模拟。作品保留真实源墨斑，通过构图选择、高度求解和相机展示形成视觉结果；具体轮廓包含算法塑形，并非未经设计的自发物体。
